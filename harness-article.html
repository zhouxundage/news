01它到底是什么，不是什么

先排除三个常见误解：

它不是实际是
❌ 一个现成的 AI 助手 ✅ 一个运行时。装好后是一个 Web UI（npx @deepseek-ai/dsh web），但它真正的价值在于你能把里面任何一块换掉
❌ LangChain 那种"库" ✅ 库是你 import 它；dsh 是你挂载到它的插件树上。你的代码和它自带的功能是平级的兄弟节点，没有"主从"
❌ Claude Code 那种"产品" ✅ 产品是固定的；dsh 的 agent loop、工具集、持久化方式、甚至 UI 都是可替换的条目
一句话定位：如果 Linux 是"一切皆文件"，dsh 就是"一切皆插件"。它没有需要打补丁的特权内核——你想改什么，就写一个插件挂在旁边，原来的那个卸掉。

这带来一个直接后果：它的源码不是"读一遍就懂"的那种。283k 星的仓库有 packages/ 下几十个包、上万行配置。你不需要读完——你需要看懂它的抽象，然后用 200 行复刻那个抽象。

02五个设计决策

① 一切皆插件，包括 agent loop

官方文档的原话：模型适配器、工具注册表、会话日志、以及 agent loop 本身都是插件，"因此每个都可以从配置替换"。

这句话的分量在于：大多数 agent 框架里，loop 是框架的核心、不可动；工具和模型才是插件。dsh 把 loop 也下沉成了 ctx.agentLoop 这个服务。你想换成"先规划再执行"的两段式 loop，不需要 fork，只需要写一个实现同样接口的插件替掉它。

② Cordis：不是"插件目录"，是服务容器 + 依赖注入

底层用的 Cordis。它的五个概念，是理解 dsh 的最小知识集：

概念含义在 dsh 里的例子
插件一个实现 Service 的对象：函数带 apply(ctx)，或 Service 子类一个工具包、一个模型适配器
上下文 ctx服务容器。服务占一个稳定的 key，别人按 key 找，不 import 实现ctx.tools、ctx.llm、ctx.sessions
inject声明依赖的服务名；等这些服务就绪才启动inject = ['tools']
类型化事件用 TS 声明合并注册事件名，五种分发方式tools/pre-execute（拦工具调用）
可逆副作用注册都返回 disposer，卸载时自动撤销卸插件 = 工具自动消失

这五条里最容易被低估的是最后一条。它意味着热插拔不是靠"重启动"，而是靠"引用计数"：谁注册的谁负责撤销，一条 ctx.effect() 串起整个生命周期。

③ 事件分三域：会话、agent、能力

扩展点不是一锅粥，而是按"你要改的东西的性质"分成三类：

session/* —— 持久事实

追加到日志、重载后还在。比如 turn/start、tool/result。用在你需要事后能查到的东西上。

agent/* —— 进行中的工作

携带活跃 Agent：inbox、step、状态、请求、验证。用在你需要拦截或观察"正在发生的事"上。

capability seam —— 插件挂策略

fs/*、tools/*、telemetry/*。用在你不 import 循环也能加中间件上。

为什么分域

因为"改日志格式"和"拦工具调用"是两种完全不同的需求。混在一个事件总线里，插件会互相踩。

④ 五种事件分发方式（这个设计很讲究）

模式是否 await语义典型用途
emit否扇出，无返回值通知、日志
waterfall否环绕中间件，可包装/短路策略门禁、改写请求
parallel是全部并行并行检查
serial是按序，有返回值链式决策
bail否停在首个返回值快速否决

waterfall 是最关键的：监听器拿到 (...args, next)，调 next() 就把控制权交给下游，不调就短路。这就是"权限门禁"的实现方式——策略插件站在链条最前面，看到不该放行的调用，直接返回，后面的执行器根本不会被调用。

⑤ profile / bundle / patch：配置也是分层的

运行时不是"一个配置文件"，而是四层叠加：

profile（web / headless / sdk / sdk-minimal / acp）
  └─ 有序的 bundle：dsh-base → dsh-web-app
      └─ cordis.patch.yml（profile 的补丁）
          └─ home patch
              └─ --patch overlay（命令行临时覆盖）

每层都按 id 定位某个条目，替换它的 config 或插入新条目。所以"改一个内置行为"不是一个 PR，而是一行 YAML。这套机制让"定制"和"升级"不再冲突——这是很多框架做不到的。

想看你机器上真实的树：dsh --profile web --dump-config。它打印出的任何条目都能被你的 patch 替换——这句话是官方文档里最有价值的一句。

03agent loop 的真实流程

官方把一次交互拆成两层：turn（轮）和 step（步）。

turn（轮）

从"领取第一条输入"开始，到"不再欠任何工作"结束。一个 turn 包含零个或多个 step。用户说一句话、agent 调了三次工具、最后回答——这是一个 turn。

step（步）

一次模型请求 + 它发起的工具调用。工具返回结果后如果还需要再问模型，就进入下一个 step——所以 step 循环发生在 turn 内部。

完整时序（把官方伪代码翻译成人话）

turn/start
├─ 领取「下一条要处理的输入」+ 至多一条排队消息
├─ 快照本次的模型选择；组装 system prompt 片段 + 本步允许的工具 schema
├─ agent/pre-step            ← 插件可在这里改写或拒绝
├─ step/start
│   ├─ agent/request          ← 绑定一次具体的模型调用（可取消）
│   ├─ 追加 user/message 到日志；冻结模型历史
│   ├─ 流式调用模型 → llm/stream → agent/assistant-stream（chunk × N）
│   ├─ 得到 assistant/message（或 attempt）
│   ├─ tool/call × N
│   │   ├─ tools/pre-execute  ← 策略门禁（允许/拒绝/询问）
│   │   ├─ tools/execute      ← 截止时间、重试、指标
│   │   ├─ tools/post-execute ← 替换展示、附加上下文
│   │   └─ tool/result × N
│   └─ step/end
├─ 如果「还欠一次模型请求」或「新输入到了」→ 回到 step/start
└─ agent/turn-stopping → turn/end
三个容易忽略的设计：
① turn 可以在零 step 的情况下关闭——比如策略插件在 pre-step 阶段就把请求拒了。
② 「还欠一次请求」是显式状态，不是靠"工具返回了就一定再问"。有的工具返回后可以直接结束（比如终止类工具）。
③ 日志是事实源：模型历史是从会话日志里冻结出来的，不是从内存里的 messages 数组。重载后能完全复原。

事件分类（哪些能重放，哪些不能）

类型事件
持久会话事件（写进日志，重载可复原）turn/*、step/*、system/message、user/message、assistant/message、assistant/attempt、tool/*
实时扩展点（只在内存里）agent/pre-step、agent/request、agent/turn-stopping、tools/pre-execute 等
进程本地流（不持久）agent/assistant-stream 的 start / chunk / end

这个划分直接决定你写插件时该挂哪个事件：要事后能查到 → 挂持久事件；要拦行为 → 挂实时扩展点。

04工具怎么写

这是官方文档里的最小形态，不是我编的：

import { readFile } from 'node:fs/promises'
import { defineTool } from '@deepseek-ai/dsh-tools'

export const name = 'my-tool'
export const inject = ['tools']        // 声明依赖：等 ctx.tools 就绪才启动

export function apply(ctx) {
  ctx.tools.register(defineTool({
    name: 'read_file',
    description: 'Read a file from disk.',     // 模型看到的
    parameters: {
      path:  { type: 'string', required: true, description: 'Absolute path' },
      limit: { type: 'number' },                    // 默认可选
    },
    output: {
      schema: { type: 'string' },
      render: (_args, value) => [{ type: 'text', text: value }],
    },
    async execute(args, exec) {
      // args 已按 schema 校验过并推导出类型
      // exec 携带不可变身份 + token；signal 是可操作字段
      return readFile(args.path, { encoding: 'utf8', signal: exec.signal })
    },
  }))
}

这段 30 行代码里藏了 6 个约定，每个都对应一个常见的坑：

约定为什么
注册是可逆副作用dispose 插件 = 工具自动注销。你不需要写"卸载函数"，生命周期由容器管
schema 自动进 system prompt你只写一次，模型看到的就是它；不用另外维护一份"工具说明"
参数已校验defineTool 在 execute 之前按 schema 校验（类型、必填、联合、嵌套）。你只需检查 schema 表达不了的东西（非空字符串、正数、跨字段）
执行身份不可变exec.token / callId / agent 在整条分发链上冻结。args 当只读，只有环绕包装器能拿到可变视图
返回规范 JSON 值不要在工具里拼自然语言让人去解析。返回结构化值，渲染交给 output.render
异常 = isError抛 HarnessError 子类并带稳定 code；异常不会打断 loop，会变成工具结果回给模型
最容易写错的一条：把策略内建进工具。官方明确说"尽量不要把部署策略内建到工具中"——允许/拒绝放 tools/pre-execute，超时重试放 tools/execute，展示替换放 tools/post-execute。工具本身只做一件事。

05三层复刻路径

"复刻"有三个层次，成本差 100 倍。先想清楚你要哪一层。

L1：直接用（3 分钟）

npx @deepseek-ai/dsh web        # 默认起在 http://127.0.0.1:3080

能看到完整产品，但你对内部一无所知。适合先判断"这东西值不值得学"。

L2：写插件扩展（30 分钟）

# 1. 看它启动了什么树
dsh --profile web --dump-config

# 2. 在你的 profile 里加一个插件条目
# ~/.dsh/profiles/web/cordis.patch.yml
- id: my-tool
  config: { greeting: "hi" }

然后写一个 apply(ctx) 注册工具或挂事件。这一步能让你真正理解"插件"和"事件"是什么手感，但你还是不知道 loop 怎么转。

L3：自己搭一个（1–2 天）

不依赖 dsh，实现同样的抽象：服务容器 + 事件总线 + 可逆副作用 + 工具注册表 + turn/step 循环。下面是完整实现，200 行，只用 Python 标准库。

为什么值得走 L3：框架的 API 会变，抽象不会。你把"ctx 是容器""事件是中间件""注册要可逆"这三件事写一遍，以后看任何 agent 框架（LangGraph、AutoGen、Claude Code SDK）都是同一个骨架的不同方言。

06200 行复刻

下面这份代码我实际跑过，输出在代码后面。它实现了 dsh 的 5 个核心抽象，删掉了所有工程细节（沙箱、审批、压缩、UI）。

"""
mini_agent.py —— 与 DeepSeek Harness 同构的最小 agent 内核
跑法：python3 mini_agent.py
不需要任何依赖，只用标准库。
"""
import json
import os
from dataclasses import dataclass
from typing import Any, Callable


# ============ 1. 上下文：服务容器 + 事件总线 ============
class Context:
    """Cordis 的 ctx 的最小翻版：服务按 key 存放，事件按名字分发，注册可撤销。"""

    def __init__(self):
        self._services: dict[str, Any] = {}
        self._disposers: list[Callable[[], None]] = []
        self._listeners: dict[str, list] = {}

    # --- 服务 ---
    def set(self, key: str, svc: Any) -> None:
        self._services[key] = svc

    def get(self, key: str) -> Any:
        return self._services[key]

    # --- 可逆副作用：返回 disposer，卸载时统一回收 ---
    def effect(self, dispose: Callable[[], None]) -> Callable[[], None]:
        self._disposers.append(dispose)
        return dispose

    def dispose(self) -> None:
        while self._disposers:
            self._disposers.pop()()

    # --- 事件 ---
    def on(self, event: str, fn: Callable, prepend: bool = False) -> Callable[[], None]:
        lst = self._listeners.setdefault(event, [])
        lst.insert(0, fn) if prepend else lst.append(fn)

        def off() -> None:
            if fn in lst:
                lst.remove(fn)

        return self.effect(off)

    def emit(self, event: str, **kw) -> None:
        for fn in list(self._listeners.get(event, [])):
            fn(**kw)

    def waterfall(self, event: str, value: Any, **kw) -> Any:
        """环绕中间件：监听器签名 f(value, next_, **kw)，不调 next_ 即短路。"""
        chain = list(self._listeners.get(event, []))

        def step(v: Any, i: int) -> Any:
            if i >= len(chain):
                return v
            fn = chain[i]
            return fn(v, lambda nv=None: step(v if nv is None else nv, i + 1), **kw)

        return step(value, 0)


# ============ 2. 工具注册表 ============
@dataclass
class Tool:
    name: str
    description: str
    params: dict          # {参数名: {type, required, description}}
    run: Callable         # run(args, ctx) -> 任意可 JSON 序列化的值

    def schema(self) -> dict:
        props = {k: {kk: vv for kk, vv in v.items() if kk != "required"}
                 for k, v in self.params.items()}
        required = [k for k, v in self.params.items() if v.get("required")]
        return {
            "name": self.name,
            "description": self.description,
            "input_schema": {"type": "object", "properties": props, "required": required},
        }


class Tools:
    def __init__(self):
        self._tools: dict[str, Tool] = {}

    def register(self, tool: Tool) -> Callable[[], None]:
        self._tools[tool.name] = tool
        return lambda: self._tools.pop(tool.name, None)

    def schemas(self) -> list[dict]:
        return [t.schema() for t in self._tools.values()]

    def call(self, name: str, args: dict, ctx: Context) -> Any:
        if name not in self._tools:
            raise KeyError(f"unknown tool: {name}")
        return self._tools[name].run(args, ctx)


# ============ 3. Agent loop（turn / step 两层） ============
class Agent:
    """一个 turn 包含零或多个 step；一个 step = 一次模型请求 + 它发起的工具调用。"""

    def __init__(self, ctx: Context, model: Callable, system: str, log_path: str):
        self.ctx = ctx
        self.model = model
        self.system = system
        self.log_path = log_path

    def _log(self, event: str, **kw) -> None:
        os.makedirs(os.path.dirname(self.log_path), exist_ok=True)
        with open(self.log_path, "a", encoding="utf-8") as f:
            f.write(json.dumps({"event": event, **kw}, ensure_ascii=False) + "\n")

    def run_turn(self, user_message: str, max_steps: int = 8) -> str:
        self._log("turn/start")
        self.ctx.emit("turn/start", message=user_message)

        messages = [
            {"role": "system", "content": self.system},
            {"role": "user", "content": user_message},
        ]
        tools = self.ctx.get("tools")

        for _ in range(max_steps):
            # 扩展点：插件可以在模型调用前改写消息（返回 None 表示拒绝这一步）
            pending = self.ctx.waterfall("agent/pre-step", messages)
            if pending is None:
                self._log("turn/end", reason="rejected")
                return ""

            self._log("step/start")
            reply = self.model(pending, tools.schemas())
            self._log("assistant/message", content=reply.get("content", ""))
            messages.append(reply)

            calls = reply.get("tool_calls") or []
            if not calls:
                self._log("turn/end", reason="done")
                self.ctx.emit("turn/end", reply=reply.get("content", ""))
                return reply.get("content", "")

            for call in calls:
                decision = self.ctx.waterfall("tools/pre-execute", call)
                if decision is None:                      # 被策略插件拦下
                    result = {"error": "denied by policy"}
                else:
                    try:
                        result = tools.call(call["name"], call.get("arguments", {}), self.ctx)
                    except Exception as exc:              # 工具异常 = isError，不打断 loop
                        result = {"error": f"{type(exc).__name__}: {exc}"}
                result = self.ctx.waterfall("tools/post-execute", result, call=call)

                messages.append({
                    "role": "tool",
                    "tool_call_id": call["id"],
                    "content": json.dumps(result, ensure_ascii=False)[:4000],
                })
                self._log("tool/result", name=call["name"], result=str(result)[:200])

        self._log("turn/end", reason="max_steps")
        return "(达到最大步数)"


# ============ 4. 插件：就是一个函数 ============
def filesystem_plugin(ctx: Context) -> None:
    """注册 read_file 工具；插件卸载时工具自动注销。"""

    def read_file(args: dict, _ctx: Context) -> str:
        path = os.path.abspath(args["path"])
        with open(path, encoding="utf-8") as f:
            return f.read()[:4000]

    ctx.effect(ctx.get("tools").register(Tool(
        name="read_file",
        description="Read a UTF-8 text file from disk.",
        params={"path": {"type": "string", "required": True, "description": "绝对路径"}},
        run=read_file,
    )))


def guard_plugin(ctx: Context) -> None:
    """策略插件：拦掉路径不在白名单里的读操作（对应 dsh 的 tools/pre-execute）。"""

    def gate(call: dict, next_, **_):
        args = call.get("arguments", {})
        if call["name"] == "read_file" and "/etc/" in str(args.get("path", "")):
            return None                     # 不调 next_ = 短路，直接拒绝
        return next_(call)

    ctx.on("tools/pre-execute", gate, prepend=True)


def audit_plugin(ctx: Context) -> None:
    """观测插件：只记录，不改行为（对应 tools/post-execute）。"""

    def audit(result, next_, call=None, **_):
        print(f"  [audit] {call[&#x27;name']} -> {str(result)[:60]}")
        return next_(result)      # 观察者必须委托，否则会短路

    ctx.on("tools/post-execute", audit)


# ============ 5. 组装并跑一个 turn ============
def fake_model(messages, schemas) -> dict:
    """用一个假模型验证 loop：第一轮调 read_file，第二轮直接回答。"""
    already = any(m.get("role") == "tool" for m in messages)
    if not already:
        return {
            "role": "assistant",
            "content": "",
            "tool_calls": [{"id": "call_1", "name": "read_file",
                            "arguments": {"path": os.path.abspath(__file__)}}],
        }
    last = [m for m in messages if m.get("role") == "tool"][-1]["content"]
    return {"role": "assistant", "content": f"文件前 80 字：{last[:80]}"}


if __name__ == "__main__":
    ctx = Context()
    ctx.set("tools", Tools())

    for plug in (filesystem_plugin, guard_plugin, audit_plugin):
        plug(ctx)

    agent = Agent(ctx, fake_model, "你是一个极简 agent。", "/tmp/mini_agent_session.jsonl")
    print("turn 开始")
    out = agent.run_turn("读一下 mini_agent.py 的开头")
    print("回复:", out)
    print("\n会话日志:")
    with open("/tmp/mini_agent_session.jsonl", encoding="utf-8") as f:
        for line in f:
            print("  ", line.replace("\n", "")[:150])
    ctx.dispose()
    print("\n插件已卸载，工具数:", len(ctx.get("tools")._tools))

07你的版本和它的差距

跑通 200 行之后，你会立刻意识到差距不在"loop 怎么写"，而在这张表上：

能力dsh 的做法要不要自己补
上下文压缩独立插件，按 token 预算自动摘要，事件可观测生产必补，最难补
沙箱与审批策略插件 + 危险级别 + 人工确认卡片涉及安全，必须补
会话持久化JSONL + 版本号 + 检查点 + 格式迁移想要"断点续跑"就补
子 agent运行时树成员关系，独立作用域多任务并行时补
MCP统一挂载一次，客户端条目即插即用要接外部工具时补
多模型适配适配器 seam，流式词汇表统一换模型时补
UIWeb / Electron / ACP / SDK 四种壳看你要不要给人用
结论：200 行给你的是骨架正确。骨架错了，后面每加一个功能都会更痛；骨架对了，补这些是体力活而不是重写。这也是为什么值得先走一遍 L3。

08什么时候不该用它

说点反向的：

  • 它明确处于"开发者预览"。官方 README 写了"未来将出现破坏兼容性的变更"。你要做长期产品，得接受某天配置树重构。
  • TypeScript 生态。插件是 TS 写的。你的技术栈是 Python/R 的话，L3 自建或换成 Python 系的框架更省事。
  • 配置即代码的代价。profile / bundle / patch 四层很优雅，但调试"为什么这个插件没生效"要翻四层 YAML。
  • 它不替你做产品决策。它给你一个可重组的运行时，但"agent 该有几个工具""什么时候该停"仍然要你自己想。
给你的一句判断：如果你要的是"一个能跑的 agent"，npx 一行就够，别浪费时间读源码。
如果你要的是"知道 agent 到底怎么运转、并且能在自己的场景里改它"，花两天把 200 行写一遍，比读 dsh 的一万行配置值。
