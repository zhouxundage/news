01它是什么：四个层次

"Claude Code 是什么"这个问题之所以经常答错，是因为它同时是四样东西。官方自己列了张对照表：

层次是什么什么时候用
CLI 产品 终端里的交互式 agent：claude 人机协作编码、一次性任务
Agent SDK Python / TypeScript 库，打包了同一套 loop、工具和上下文管理 你要在程序里跑 agent，但不想自己写工具循环
Client SDK Anthropic Messages API 的客户端 你要完全自己实现 loop
Managed Agents 托管 REST API，Anthropic 替你跑沙箱和会话 长任务、异步、不想管基础设施
关键事实：Agent SDK 里跑的是同一个 loop，而且是打包了一个原生 Claude Code 二进制在里面的。所以"用 SDK"和"用 CLI"在内核上是一回事，区别只在控制面。

这也解释了它为什么闭源但可以学：产品闭源，但 loop 的每一步都在 SDK 的消息流里吐出来。你观察不到源码，但你能观察到每一个决策点。

和 DeepSeek Harness 的根本差异

维度DeepSeek HarnessClaude Code
内核（loop）插件，可替换固定，不可换
扩展方式挂载同构插件，改配置树在外围挂载点上挂钩子
开源MIT，源码全可见闭源，只有 SDK 和文档
可观测性读日志 + 读源码SDK 消息流（5 种消息）
适合谁要重组 agent 架构的人要一个已经调好的 coding agent 的人

一句话：dsh 赌"你会想改内核"，Claude Code 赌"你不想改内核，但想改一切其它东西"。后者在工程上更保守，也更容易做出稳定产品。

02五个设计决策

① 工具集刻意做小，把通用能力交给 bash

内置工具只有六个核心：Read、Write、Edit、Glob、Grep、Bash，加两个 Web 工具。

注意它没有：rename 工具、mkdir 工具、git 工具、包管理工具、测试工具。这些全部通过 Bash 完成。

这是一个非常克制的选择：工具越少，模型选错的概率越低；bash 是唯一的"万能后门"。代价是每次 shell 调用都是一次权限决策点——所以它的权限系统必须做得足够细。

② 上下文是核心资产，不是副产品

Claude Code 花在"管理上下文"上的设计，比花在"调用模型"上的多得多：

机制作用
CLAUDE.md 层级企业级 → 项目级 → 用户级，自动加载；另有 .claude/rules/*.md 可懒加载
自动压缩接近窗口上限时摘要历史，保留任务状态
Subagent 隔离子任务在独立上下文里跑，只把结论带回主线
Skills 渐进披露技能描述先入上下文，正文按需加载——不占常驻预算
InstructionsLoaded 事件连"哪个文件被加载进上下文"都做成了可观测事件

最后一条很说明问题：它把上下文加载本身当成了需要审计的事。

③ 权限不是布尔开关，是一条求值链

这是 Claude Code 最被低估的设计。一次工具调用的放行要过五关：

工具调用请求
   ↓
① hooks（PreToolUse）         ← 自定义脚本，可 allow / deny / 修改入参
   ↓
② deny 规则（disallowed_tools / settings）  ← 命中即拒，bypassPermissions 也拦不住
   ↓
③ ask 规则（settings.json）    ← 命中就一定要问人
   ↓
④ permission mode             ← default / acceptEdits / plan / dontAsk / auto / bypassPermissions
   ↓
⑤ canUseTool 回调             ← 程序里的最后一道人工确认
   ↓
执行
顺序不能反。deny 规则在 hook 之后、ask 之前——意味着即使你的 hook 返回 allow，deny 规则仍然能否决。这是"策略不能被绕过"的体现：越靠后的关卡优先级越高。反过来，onFailure: "block" 才让超时的 hook 真正起到门禁作用，否则 hook 崩了就等于全放行。

④ 扩展点全在外围，一圈一圈套

挂载点管什么典型用法
hooks生命周期事件：会话开始、提交提示、工具前后、结束自动格式化、审计日志、拦危险命令
skills领域知识与流程，按需加载把你的团队规范固化成可复用技能
subagents独立上下文的子任务执行者让"搜索 20 个文件"不污染主线
MCP外部工具/数据源协议接数据库、Jira、内部 API
plugins把上面几样打包分发团队级能力共享

⑤ 内核固定，但每一步都可观测

Agent SDK 会吐五类消息，覆盖 loop 的完整生命周期：

消息类型含义
SystemMessage会话初始化（subtype=init），带 session 元数据
AssistantMessage每个内容块一条：文本块、工具调用块各一条
UserMessage工具执行结果回传给模型（也用于中途插入的用户输入）
StreamEvent开启部分消息时的原始流事件（文本增量、工具入参增量）
ResultMessageloop 结束：最终文本、token 用量、成本、session id、subtype 表示成功还是撞上限
实战提醒：官方文档专门写了一句"ResultMessage 之后还可能来少量尾部系统事件，要迭代到流结束，不要看到 result 就 break"。这是一个真实的坑——很多人在这里丢消息。

03loop 的真实流程

官方把自己的 loop 描述成"三阶段混合"，但在 SDK 层面是五步：

① 收提示prompt + system + 工具定义 + 历史
→
② 评估可能回文本、可能要工具、可能都要
→
③ 执行工具hooks 可拦截/修改/阻断
→
④ 循环结果回灌，回到②
→
⑤ 结束无工具调用的那条回复即终止

而"三阶段"是给人类看的认知模型：

gather context（读代码、搜文件）
      ↕  反复混合
take action（编辑、跑命令）
      ↕
verify results（跑测试、看错误）

三个阶段的边界是模糊的——一个 bug fix 可能循环"读→改→测"十几次。真正控制它停下来的，是模型自己判断"这次不需要再调工具了"，而不是外部的计数器。

turn 的定义：一次 pass 过 loop（模型输出 + 它引发的工具执行 + 结果回灌）。turn 结束的条件是"模型输出了不带工具调用的回复"。所以"轮数"是结果，不是参数——你能设的是 max_turns 上限，不是"跑三轮就停"。

04工具怎么写

Claude Code 内置工具你是改不了的，但 Agent SDK 允许两种扩展：

  1. 进程内 MCP server —— 用 SDK 的 tool() 辅助函数定义，跑在你自己的进程里，不需要起服务
  2. 自定义 tool（TS SDK）—— 直接给工具定义加 permission_policy 等字段

形态与 dsh 的 defineTool 很像，因为两者都遵循同一个事实标准：JSON Schema 描述入参 + 一个 async 执行函数。

# Python SDK：进程内工具
from claude_agent_sdk import tool, create_sdk_mcp_server

@tool("read_file", "Read a file", {"path": str})
async def read_file(args):
    return {"content": [{"type": "text", "text": open(args["path"]).read()}]}

server = create_sdk_mcp_server(name="my-tools", tools=[read_file])

三个和 dsh 不同的地方

对比项dshClaude Code
参数校验框架按 schema 自动校验，execute 拿到已校验的 args框架校验后传入，但你仍要处理业务约束
权限挂在 tools/pre-execute 事件上挂在 hooks + 规则 + mode 三层上，且有固定优先级
输出返回规范 JSON 值，output.render 负责展示返回 MCP 的 content 块（文本/图片/资源）
关于"工具里写策略"：两个框架的态度一致——不要在工具内部判断"该不该执行"，把它交给外层的策略层。区别是 dsh 用事件，Claude Code 用权限链。后者更难绕过，但更难调试。

05三层复刻路径

L1：直接用（0 分钟，但要订阅或 API key）

npm install -g @anthropic-ai/claude-code
claude                      # 交互式
claude -p "修一下 auth 的测试" --output-format json   # 无头模式

无头模式是自动化最常用的入口：-p 加 --output-format json，就能把它当命令行工具嵌进脚本。

L2：Agent SDK（20 行，拿到同款 loop）

import asyncio
from claude_agent_sdk import query, AssistantMessage, ResultMessage, TextBlock

async def main():
    async for message in query(prompt="Summarize this project"):
        if isinstance(message, AssistantMessage):
            for block in message.content:
                if isinstance(block, TextBlock):
                    print(f"Claude: {block.text}")
        if isinstance(message, ResultMessage) and message.subtype == "success":
            print(message.result)

asyncio.run(main())

这一步你能拿到：内置工具、权限控制、hooks、subagent、MCP、成本统计。代价是它把 loop 封装了——你能观测，但改不了。

L3：自己写 loop（150 行，完全掌控）

用 Anthropic Messages API，把 tool_use / tool_result 的循环手写一遍。下面这份代码我实际跑过（mock 模式验证循环结构，把 ANTHROPIC_API_KEY 设上就是真实调用）。

06150 行复刻

"""
mini_claude.py —— 用 Anthropic Messages API 复刻 Claude Code 的 agent loop
无第三方依赖，只用标准库。

有 key：ANTHROPIC_API_KEY=sk-ant-... python3 mini_claude.py "读一下 README"
无 key：自动进入 mock 模式，用假响应验证循环结构
"""
import json
import os
import urllib.error
import urllib.request

API = "https://api.anthropic.com/v1/messages"
MODEL = os.environ.get("CLAUDE_MODEL", "claude-sonnet-4-5")
KEY = os.environ.get("ANTHROPIC_API_KEY", "").strip()

SYSTEM = """你是一个命令行 coding agent。你可以读写文件、跑命令。
先理解再动手；改完代码要自己验证。回答简洁。"""

# ---------- 1. 工具定义：就是 Claude Code 内置的那几个 ----------
TOOLS = [
    {
        "name": "read_file",
        "description": "Read a UTF-8 text file. Use it before editing anything.",
        "input_schema": {
            "type": "object",
            "properties": {
                "path": {"type": "string", "description": "绝对路径"},
                "limit": {"type": "integer", "description": "最多读多少行"},
            },
            "required": ["path"],
        },
    },
    {
        "name": "bash",
        "description": "Run a shell command in the workspace. Returns stdout+stderr.",
        "input_schema": {
            "type": "object",
            "properties": {"command": {"type": "string"}},
            "required": ["command"],
        },
    },
]


# ---------- 2. 工具执行：一个字典派发 ----------
def run_tool(name: str, args: dict) -> str:
    if name == "read_file":
        path = os.path.abspath(args["path"])
        if "/etc/" in path or path.startswith("/root"):
            raise PermissionError(f"path not allowed: {path}")
        with open(path, encoding="utf-8", errors="replace") as f:
            lines = f.readlines()
        limit = args.get("limit") or 200
        return "".join(lines[:limit])[:8000]

    if name == "bash":
        import subprocess
        p = subprocess.run(args["command"], shell=True, capture_output=True,
                           text=True, timeout=30, cwd=os.getcwd())
        return (p.stdout + p.stderr)[:8000] or f"(exit {p.returncode}, no output)"

    raise KeyError(f"unknown tool: {name}")


# ---------- 3. 一次模型调用 ----------
def call_model(messages: list) -> dict:
    if not KEY:
        return _mock(messages)

    body = json.dumps({
        "model": MODEL,
        "max_tokens": 2000,
        "system": SYSTEM,
        "tools": TOOLS,
        "messages": messages,
    }).encode()

    req = urllib.request.Request(API, data=body, method="POST", headers={
        "content-type": "application/json",
        "x-api-key": KEY,
        "anthropic-version": "2023-06-01",
    })
    with urllib.request.urlopen(req, timeout=120) as r:
        return json.loads(r.read())


# ---------- 4. agent loop：整个 Claude Code 的心脏 ----------
def run_agent(prompt: str, max_turns: int = 10, verbose: bool = True) -> str:
    messages = [{"role": "user", "content": prompt}]

    for turn in range(1, max_turns + 1):
        resp = call_model(messages)
        blocks = resp.get("content", [])
        stop = resp.get("stop_reason")

        if verbose:
            for b in blocks:
                if b["type"] == "text" and b["text"].strip():
                    print(f"[turn {turn}] 模型: {b['text'].strip()[:160]}")
                elif b["type"] == "tool_use":
                    print(f"[turn {turn}] 调用: {b['name']}({json.dumps(b['input'], ensure_ascii=False)})")

        # 关键：把模型的整条回复原样放回历史（含 tool_use 块），否则下一轮会 400
        messages.append({"role": "assistant", "content": blocks})

        if stop != "tool_use":
            return "".join(b["text"] for b in blocks if b["type"] == "text")

        # 执行所有工具，结果必须一条消息批量回传
        results = []
        for b in blocks:
            if b["type"] != "tool_use":
                continue
            try:
                out = run_tool(b["name"], b["input"])
                is_err = False
            except Exception as exc:                      # 工具失败也要回给模型
                out, is_err = f"{type(exc).__name__}: {exc}", True
            results.append({
                "type": "tool_result",
                "tool_use_id": b["id"],
                "content": out,
                "is_error": is_err,
            })
            if verbose:
                print(f"          → {out[:100].replace(chr(10), ' ')}")

        messages.append({"role": "user", "content": results})

    return "(达到最大轮数，已中止)"


# ---------- 5. 无 key 时的假模型：只验证循环结构 ----------
def _mock(messages: list) -> dict:
    has_tool = any(
        isinstance(m.get("content"), list) and any(
            isinstance(b, dict) and b.get("type") == "tool_result" for b in m["content"])
        for m in messages
    )
    if not has_tool:
        return {
            "content": [
                {"type": "text", "text": "先看一下 mini_claude.py 的开头。"},
                {"type": "tool_use", "id": "toolu_01", "name": "read_file",
                 "input": {"path": os.path.abspath(__file__), "limit": 6}},
            ],
            "stop_reason": "tool_use",
        }
    last = [b for m in messages if isinstance(m.get("content"), list)
            for b in m["content"] if isinstance(b, dict) and b.get("type") == "tool_result"][-1]
    return {
        "content": [{"type": "text", "text": f"读到了，前几行是：\n{last['content'][:120]}"}],
        "stop_reason": "end_turn",
    }


if __name__ == "__main__":
    import sys
    task = sys.argv[1] if len(sys.argv) > 1 else "读一下 mini_claude.py 的开头，告诉我它是什么"
    print(f"模式: {'真实 API' if KEY else 'mock（无 ANTHROPIC_API_KEY）'}\n")
    print("最终回答:\n" + run_agent(task))

[turn 1] 调用: read_file({"path": ".../mini_claude.py", "limit": 6})
          → """ mini_claude.py —— 用 Anthropic Messages API 复刻 Claude Code 的 agent loop ...
[turn 2] 模型: 读到了，前几行是：...
最终回答:
读到了，前几行是：...

这 150 行里有三个必须做对的地方

要点做错的后果
assistant 消息要原样回灌（含 tool_use 块）下一轮 API 直接 400：tool_use ids were found without tool_result blocks
所有 tool_result 必须打包进同一条 user 消息并行工具调用时会被判为不完整，同样 400
工具抛错也要回传，用 is_error: true模型永远等不到结果，loop 卡死或超时
这就是"复刻"和"照抄"的区别：loop 的骨架只有 30 行，剩下 120 行全在处理协议细节和错误路径。dsh 那篇的 200 行里，一半也是这个。

07你和它之间的真实差距

跑通之后你会发现，差距不在 loop，而在这张表上：

能力Claude Code 的做法自己补的成本
上下文压缩接近上限自动摘要，保留任务状态高（要设计"什么必须留"）
权限系统五关求值链 + 六种模式 + 规则文件中（逻辑不复杂，但边界多想不清）
编辑工具Edit 用字符串替换 + 失败重试，不是整文件覆盖中（diff 匹配的坑很多）
并发工具同一轮多个 tool_use 并行执行低（asyncio 就够）
Subagent独立上下文 + 独立工具权限 + 结果汇总中
成本控制token 用量、美元成本、max_turns、预算上限低
会话恢复session id + 存档 + 续跑中

08什么时候不该用它

  • 你要改 loop 本身。比如"先规划三步再执行"、"两阶段验证"，Claude Code 的 loop 是固定的，你只能在外围拐弯。这种情况 dsh 更合适。
  • 你需要完全离线或私有部署。它是云服务 + 闭源二进制，没有自托管路径。
  • 你的场景不是 coding。工具集（Read/Edit/Bash/Glob/Grep）和 prompt 都是为代码库调的；拿去做客服或数据分析，要重写的东西不少。
  • 你付不起按 token 计费。长会话 + 大代码库，成本增长比想象快，务必设 max_turns 和预算上限。
两篇的结论合起来看：
要改架构 → DeepSeek Harness（内核可换）。
要尽快做出稳定的 coding agent → Claude Code + Agent SDK。
要真正理解 agent 怎么转 → 两篇的 200 行 / 150 行都亲手写一遍。这一步没有替代品。
